## 문제 상황

초대 링크를 받은 사용자는 로그인하기 전에도 초대 대상이 어떤 여행방인지 확인할 수 있어야 한다. 현재 초대 코드 미리보기와 초대 코드로 합류하는 API가 없어, 초대받은 사용자가 방 정보를 확인하거나 방에 들어갈 수 없다. 초대 코드는 방 접근 권한을 가진 비밀 값으로 취급해야 하며, 탈퇴한 멤버의 기록은 보존하고 재합류를 막아야 한다.

## 해결 방향

로그인 없이 방 초대 미리보기를 제공하고, 로그인한 사용자에게 초대 코드로 방 합류를 제공한다. 미리보기는 합류에 필요한 최소 정보와 합류 가능 여부를 알려준다. 합류는 방 잠금과 기존 멤버 이력 확인을 같은 트랜잭션에서 수행하고, 멤버 추가와 방 활동 내역을 함께 저장한다.

## 사용자 스토리

1. 초대받은 방문자로서, 로그인하기 전에 초대 코드로 여행방의 기본 정보를 확인하고 싶다. 그래야 합류할 방이 맞는지 판단할 수 있다.
2. 비로그인 방문자로서, 초대 미리보기를 로그인 없이 열고 싶다. 그래야 로그인 전에 초대 링크를 확인할 수 있다.
3. 비로그인 방문자로서, 미리보기에서 로그인이 필요하다는 안내를 받고 싶다. 그래야 로그인 후 합류를 이어갈 수 있다.
4. 로그인한 초대받은 사용자로서, 방 이름·목적지·여행 날짜·상태와 활동 멤버 수를 확인하고 싶다. 그래야 합류 여부를 결정할 수 있다.
5. 초대받은 방문자로서, 미리보기에서 멤버 이름과 초대 코드를 볼 수 없기를 원한다. 그래야 다른 멤버의 이름과 재사용 가능한 비밀 코드를 불필요하게 노출하지 않는다.
6. 초대받은 방문자로서, 합류 후 설문이 필요한지 알고 싶다. 그래야 다음에 해야 할 일을 알 수 있다.
7. 초대받은 방문자로서, 존재하지 않는 초대 코드를 입력했을 때 명확한 오류를 받고 싶다. 그래야 잘못된 링크를 구분할 수 있다.
8. 운영자로서, 오류 로그에 초대 코드 원문이 남지 않기를 원한다. 그래야 로그가 노출되어도 초대 코드가 유출되지 않는다.
11. 로그인한 사용자로서, 초대 코드로 방에 합류하고 싶다. 그래야 초대받은 여행 계획에 참여할 수 있다.
12. 활동 멤버로서, 같은 방에 중복 합류를 요청하면 이미 멤버라는 오류를 받고 싶다. 그래야 중복 멤버가 생기지 않는다.
13. 방을 나간 사용자로서, 같은 방에 다시 합류할 수 없다는 오류를 받고 싶다. 그래야 탈퇴 이력과 방 멤버 관계가 보존된다.
14. 방 멤버로서, 합류한 멤버의 `joinedAt`과 `lastSeenAt`이 같은 합류 시각으로 설정되길 원한다. 그래야 첫 확인 시각을 합류 시점으로 일관되게 기록한다.
15. 방 멤버로서, 새 멤버의 합류 기록이 멤버 추가와 함께 저장되길 원한다. 그래야 방 멤버 목록과 방 활동 내역이 어긋나지 않는다.
16. 방 멤버로서, 새 멤버의 합류가 방 활동 내역에 한 건으로 보이길 원한다. 그래야 누가 방에 들어왔는지 알 수 있다.
17. 설문 중인 방의 멤버로서, 새 멤버가 합류해도 첫 설문 마감 시각이 연장되거나 제출을 막지 않기를 원한다. 그래야 첫 설문 마감 뒤 안건 단계와 이후 회차가 계획대로 진행된다.
18. 계획 중인 방의 멤버로서, 새 멤버가 합류했을 때 장소 후보의 동의 현황이 전체 멤버 기준으로 반영되길 원한다. 그래야 현재 멤버 전체의 합의를 볼 수 있다.
19. 계획 중인 방의 멤버로서, 이미 확정된 장소가 새 멤버 합류로 되돌려지지 않기를 원한다. 그래야 확정된 계획을 보존한다.
20. 최종 확정된 방의 멤버로서, 새 멤버를 읽기 전용으로 합류시킬 수 있길 원한다. 그래야 확정된 여행 계획을 공유할 수 있다.
21. 최종 확정된 방에 합류한 사용자로서, 추가 설문이 필요하지 않다고 안내받고 싶다. 그래야 이미 확정된 여행에서 불필요한 설문을 요구받지 않는다.
22. 안건 검토 중인 방의 멤버로서, 새 멤버가 기존 열린 안건에 투표하지 못하고 이후 열린 안건부터 자격을 얻길 원한다. 그래야 안건이 만들어질 당시의 투표 자격을 보존한다.
23. 여러 요청이 같은 방에 동시에 합류하려 해도 중복 멤버가 생기지 않기를 원한다. 그래야 동시 요청에서도 방 멤버 관계가 일관된다.
24. 방 멤버로서, 초대 코드가 틀렸으면 합류 권한이나 멤버 정보가 노출되지 않기를 원한다. 그래야 초대 코드가 방 접근 권한을 보호한다.

## 구현 결정

- 방 도메인의 기존 Controller·Service·Repository·DTO와 `ApiResponse` 응답 형식을 따른다. 상태 타입은 기존 `RoomStatus`를 사용한다.
- R-04 미리보기 경로는 로그인 없이 허용한다. 다른 방 API의 인증 요구는 그대로 유지한다.
- `GET /api/rooms/invites/{inviteCode}`는 HTTP 200, 본문 코드 `INVITE_PREVIEW_FETCHED`, 성공 메시지 없는 응답을 반환한다.
- 미리보기 응답에는 `roomId`, `name`, `destination`, `startDate`, `endDate`, `status`, `memberCount`, `joinable`, `notJoinableReason`, `surveyRequired`를 포함한다. 초대 코드와 멤버 이름은 응답하지 않는다.
- `memberCount`는 `left_at IS NULL`인 활동 멤버 수다. `status`는 미리보기에서 공개한다.
- `notJoinableReason`은 비로그인 사용자에게 `LOGIN_REQUIRED`, 로그인한 활동 멤버에게 `ALREADY_MEMBER`, 이전에 합류했다가 나간 사용자에게 `REJOIN_NOT_ALLOWED`다. 그 외 로그인 사용자에게는 `joinable: true`, 사유 `null`을 반환한다. 초대 코드가 유효하지 않으면 사용자 인증 여부와 관계없이 404 `INVITE_CODE_NOT_FOUND`다.
- `surveyRequired`는 `FINALIZED`에서만 `false`이고 다른 상태에서는 `true`다.
- 초대 미리보기에는 IP별 요청 횟수 제한을 적용하지 않는다.
- 애플리케이션 로그에 초대 코드 원문을 기록하지 않는다. 필요한 로그에는 앞 두 글자만 남기고 나머지는 마스킹한다. 모든 요청을 매번 로그로 남기지는 않는다.
- R-05 합류는 로그인 사용자만 허용한다. 비로그인 요청은 공통 401 `UNAUTHORIZED`를 반환한다.
- `POST /api/rooms/invites/{inviteCode}/join`은 요청 본문 없이 호출하며 성공 시 HTTP 200, 코드 `ROOM_JOINED`, 메시지 `여행방에 합류했습니다.`를 반환한다. 응답 데이터는 `roomId`, 새 `memberId`, `surveyRequired`다.
- 합류는 하나의 쓰기 트랜잭션으로 처리한다. 초대 코드로 방을 찾은 뒤 해당 방 행을 비관적 잠금으로 잠그고, 해당 사용자의 방 멤버 이력을 확인한 다음 새 멤버를 저장한다.
- 같은 방에 활동 멤버 기록이 있으면 HTTP 409 `ALREADY_MEMBER`, 탈퇴 기록이 있으면 HTTP 409 `REJOIN_NOT_ALLOWED`를 반환한다. 멤버 이력 복합 UNIQUE 제약조건과 방 행 잠금이 중복 합류를 막는다.
- 신규 멤버의 `joinedAt`과 `lastSeenAt`은 주입된 `Clock`의 같은 현재 시각으로 설정한다. `leftAt`은 비어 있다.
- `SURVEYING` 중 합류해도 기존 첫 설문 마감 시각을 연장하거나 제출을 막지 않으며, 이 API는 설문 상태를 바꾸지 않는다. 마감 뒤 새 설문 회차를 여는 처리는 이후 설문·안건 흐름을 따른다.
- `PLANNING` 중에는 활동 멤버 구성이 바뀌므로 장소 후보의 동의 상태는 전체 활동 멤버를 기준으로 해석한다. 이미 확정한 장소는 합류로 변경하지 않는다.
- `REVIEWING` 중에도 방 상태는 유지한다. 기존 열린 안건은 합류자의 `joinedAt`이 안건 생성 시각보다 늦어 투표 자격이 없으며, 이후 열린 안건부터 기존 자격 규칙을 적용한다.
- `FINALIZED` 방도 새 멤버 합류를 허용한다. 읽기 전용 상태를 유지하고 `surveyRequired`는 `false`로 반환한다.
- 합류 시 방 활동 내역을 멤버 추가와 같은 트랜잭션으로 저장한다. 기록은 `event_kind=MEMBER_JOINED`, `entity_type=MEMBER`, `entity_id`는 새 RoomMember ID, `action_status=CREATE`, 행위자는 합류한 멤버로 저장한다. 요약은 당시 이름을 사용해 `서연님이 합류했어요` 형식으로 저장한다.
- 활동 인원수는 ChangeLog 요약이나 저장 필드에 포함하지 않는다. ChangeLog 테이블에 구조화된 이벤트 data 컬럼을 추가하지 않는다.
- SSE 발행은 이번 구현 범위에서 제외한다. 추후 SSE 이벤트에서 필요한 data 계약과 전달 방식을 별도로 정한다.
- 최신 Flyway 파일은 V18이다. 이 API는 기존 Room, RoomMember, ChangeLog 컬럼만 사용하므로 DB 마이그레이션은 추가하지 않는다.
- 오류 코드는 `INVITE_CODE_NOT_FOUND`, `ALREADY_MEMBER`, `REJOIN_NOT_ALLOWED`를 Room 도메인에 둔다.

## 테스트 결정

- 좋은 테스트는 서비스 내부 호출 순서나 잠금 어노테이션 자체보다, HTTP에서 관찰되는 상태 코드·응답 본문·인증·멤버십 결과·저장된 방 활동 내역을 검증한다.
- `RoomInviteApiIntegrationTest` 하나를 최상위 테스트 경계로 사용한다. 실제 서버 HTTP 요청과 기존 `IntegrationTest`의 Testcontainers MySQL을 재사용한다.
- 기존 인증 사용자 생성 방식으로 로그인 세션을 준비하며, 미리보기는 쿠키 없는 요청과 로그인된 요청 모두 검증한다.
- 미리보기 테스트는 공개 필드와 비공개 필드, 각 `notJoinableReason`, `surveyRequired`, 잘못된 초대 코드의 404 응답을 확인한다.
- 합류 테스트는 상태별 `surveyRequired`, `joinedAt`·`lastSeenAt` 초기화, 활동 멤버 추가, ChangeLog의 합류 이벤트 저장을 확인한다.
- 활동 중복 합류와 탈퇴 후 재합류는 각각 409와 해당 오류 코드가 반환되고 새 멤버나 추가 기록이 생성되지 않는지 확인한다. 동시 중복 요청도 한 요청만 합류에 성공하는지 외부 HTTP 결과로 검증한다.
- 설문 마감 시각이 지난 `SURVEYING` 방에도 합류할 수 있고 마감 시각이나 상태가 바뀌지 않는지 확인한다. `REVIEWING` 합류자는 기존 안건 투표 자격이 없고 후속 안건 자격은 기존 규칙을 따르는지 확인한다.
- Testcontainers MySQL에서 기존 마이그레이션과 Hibernate 검증으로 DB 매핑 및 제약조건이 적용되는지 확인한다. 새 마이그레이션은 없다.
- 테스트 선례는 인증 흐름을 확인하는 `AuthIntegrationTest`, 방 생성 HTTP를 확인하는 `RoomCreateIntegrationTest`, 방 목록·상세의 HTTP 결과를 확인하는 `RoomReadApiIntegrationTest`다.

## 범위 밖

- 프론트엔드 초대 링크 화면, 로그인 후 원래 초대 미리보기로 복귀시키는 화면 흐름
- 방 멤버 탈퇴 API와 재합류 허용 정책
- 설문 제출, 설문 마감, 새 회차 생성 자체와 배치·스케줄러
- 장소 동의 수 갱신 로직, 확정 장소 변경, 투표·안건 상태 전이
- SSE 발행, 재연결, Outbox 및 활동 인원수 이벤트 data 저장
- DB 컬럼·인덱스 및 Flyway 마이그레이션 변경
- 방장 권한, 멤버 수 제한, 초대 코드 재발급

## 추가 참고

- 초대 코드는 현재 8자리이며 방별 고유 제약조건이 있다.
- 미리보기는 `status`와 활동 인원수를 공개하지만 멤버 이름, 초대 코드, 설문·안건별 상세 진행 내용은 공개하지 않는다.
- 미리보기의 비로그인 판정은 초대 코드 유효성 확인 후 수행해, 유효하지 않은 코드의 결과는 로그인 사용자 여부와 관계없이 일관되게 404를 반환한다.
- 방 활동 내역 용어는 용어집의 “방 활동 내역”을 따른다. 합류는 새로운 활동 멤버 관계를 만드는 행위이며, 탈퇴 기록은 보존한다.
