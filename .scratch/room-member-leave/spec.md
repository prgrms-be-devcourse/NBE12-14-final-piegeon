## Problem Statement

방 멤버가 방을 나갈 수 있는 API가 필요하다. 퇴장할 때 설문 응답, 진행 중 안건의 투표 자격, 장소 동의와 방 활동 내역이 남은 활동 멤버 기준으로 일관되게 처리되어야 한다.

## Solution

로그인한 활동 멤버가 `DELETE /api/rooms/{roomId}/members/me`를 호출해 방을 나간다. 처리는 방 잠금 안의 단일 트랜잭션으로 수행하고, 커밋 뒤 방 활동 내역과 `member.left` SSE 이벤트를 전달한다.

## User Stories

1. 활동 멤버로서, 확인 후 방에서 나가고 싶다. 그래야 더 이상 참여하지 않는 방에서 빠질 수 있다.
2. 방 멤버로서, 퇴장 요청이 성공하면 일관된 성공 응답을 받고 싶다. 그래야 화면에서 방 나가기 처리를 마칠 수 있다.
3. 방 멤버로서, 방에서 나간 뒤에는 같은 방의 API에 접근할 수 없기를 원한다. 그래야 퇴장한 멤버가 다시 방 데이터를 변경하지 못한다.
4. 방 멤버로서, 퇴장한 멤버가 다시 합류하지 못하기를 원한다. 그래야 멤버 이력과 재합류 금지 정책이 유지된다.
5. 다른 활동 멤버로서, 퇴장한 멤버의 활동 상태가 갱신되길 원한다. 그래야 현재 방 참여 인원을 알 수 있다.
6. 다른 활동 멤버로서, 퇴장한 멤버의 방 활동 내역을 보고 싶다. 그래야 멤버 구성이 바뀐 사실을 알 수 있다.
7. 설문 중인 활동 멤버로서, 퇴장한 멤버의 설문 응답이 집계에서 빠지길 원한다. 그래야 남은 멤버의 선호로 조율할 수 있다.
8. 설문 중인 활동 멤버로서, 응답 삭제 후 남은 활동 멤버 기준으로 설문 마감 조건을 다시 확인하길 원한다. 그래야 마지막 응답자가 나간 경우에도 5-1의 마감 규칙이 적용된다.
9. 안건 투표 중인 활동 멤버로서, 아직 투표하지 않은 자격자가 나가면 투표 인원에서 제외되길 원한다. 그래야 남은 멤버로 안건을 판정할 수 있다.
10. 안건 투표 중인 활동 멤버로서, 자격자 수 감소로 남은 표가 모두 같은 선택이 되면 즉시 안건이 결정되길 원한다. 그래야 불필요하게 투표 마감까지 기다리지 않는다.
11. 안건 투표 중인 활동 멤버로서, 투표 자격자가 더는 없으면 안건이 미결 마감되길 원한다. 그래야 투표자가 없는 안건이 계속 진행 중으로 남지 않는다.
12. 활동 멤버로서, 이미 투표한 사람이 방을 나가더라도 그 표가 보존되길 원한다. 그래야 이미 행사한 표와 실명 기록이 유지된다.
13. 활동 멤버로서, 이미 투표한 사람의 퇴장만으로 안건의 투표 인원이 줄지 않길 원한다. 그래야 보존된 표와 투표 분모가 일치한다.
14. 장소를 조율하는 활동 멤버로서, 퇴장한 멤버의 장소 반응이 제거되길 원한다. 그래야 남은 멤버 기준으로 장소 동의를 볼 수 있다.
15. 장소를 조율하는 활동 멤버로서, 퇴장 후 각 미확정 장소 후보의 칸이 자동으로 다시 계산되길 원한다. 그래야 남은 모든 활동 멤버가 동의했을 때 확정할 수 있다.
16. 활동 멤버로서, 이미 확정된 안건의 표와 코멘트가 보존되길 원한다. 그래야 완료된 의사 결정 기록이 바뀌지 않는다.
17. 활동 멤버로서, 퇴장한 멤버가 등록한 장소와 배치한 일정 블록이 보존되길 원한다. 그래야 다른 멤버가 기존 계획을 이어갈 수 있다.
18. 활동 멤버로서, 방 나가기 처리가 도중 실패하면 관련 데이터 변경이 함께 롤백되길 원한다. 그래야 방 상태와 참여 기록이 어긋나지 않는다.

## Implementation Decisions

- 경로는 `DELETE /api/rooms/{roomId}/members/me`이고 요청 본문은 없다. 로그인하지 않은 요청은 기존 공통 인증 오류를 따른다.
- 성공 응답은 HTTP 200, 공통 `ApiResponse<Void>`, 코드 `ROOM_LEFT`, 메시지 `방에서 나갔습니다.`를 사용한다.
- 존재하지 않는 방은 `404 ROOM_NOT_FOUND`다. 해당 방의 멤버가 아니거나 이미 나간 멤버는 `403 FORBIDDEN`이다. R-06 초안의 반복 DELETE 멱등 성공 규칙은 적용하지 않는다.
- 방 행을 먼저 잠그고 그 뒤 활동 멤버를 확인한다. 퇴장과 연관 데이터 조정 및 방 활동 내역 저장은 단일 트랜잭션으로 처리한다.
- `leftAt`은 주입된 `Clock` 기준 현재 시각으로 설정한다. 마지막 활동 멤버가 나가도 방 상태는 유지한다.
- 멤버의 설문 응답은 방 상태와 무관하게 삭제한다. 방이 설문 단계라면 응답 삭제 후 남은 활동 멤버와 응답을 사용해 명세 5-1의 설문 마감 조건을 다시 확인한다.
- `VOTING` 안건 중 퇴장 멤버가 안건 생성 시각에 투표 자격이 있었던 안건만 처리한다. 이미 `Vote`가 있으면 표와 해당 `total_voter`를 유지한다. 투표하지 않은 자격자만 `total_voter`에서 제외한다.
- 투표하지 않은 자격자의 이탈로 `total_voter`가 0이 되면 안건을 `EXPIRED`로 처리한다. 0보다 큰 경우 남은 표로 기존 7-1 규칙을 즉시 재판정하고, 해당 최종 확정 안건의 결과에 따라 기존 방 상태 전이를 적용한다.
- 퇴장 멤버의 모든 장소 후보 반응을 삭제한다. 장소 후보, 확정 시각, 확정된 안건의 표, 코멘트, 등록 장소, 일정 블록은 삭제하지 않는다. 미확정 후보의 칸은 기존 조회 계산에 따라 남은 활동 멤버 기준으로 달라지고, 확정 후보는 확정 상태를 유지한다.
- 방 활동 내역에는 `MEMBER_LEFT`를 한 건 저장한다. 방 활동 내역의 기존 `activity` 전달을 유지하고, 커밋 뒤 `member.left`라는 별도 SSE 이벤트 이름도 발행한다. 안건 결정이나 방 상태 변경에 대해 별도의 `agenda.resolved`, `room.status_changed` 이벤트 이름은 발행하지 않는다.
- `member.left` 외 SSE 전달과 방 활동 내역은 기존 ChangeLog/SSE 계약과 ADR을 따른다. 활동 멤버 조회에서 비멤버와 나간 멤버를 구분하지 않는 `FORBIDDEN` 동작은 기존 계약과 일치한다.
- DB 스키마 변경은 요구하지 않는다.

## Testing Decisions

- 좋은 테스트는 내부 메서드 호출 순서나 잠금 어노테이션보다 실제 HTTP 응답, 데이터베이스에 남은 상태, 방 활동 내역, SSE에서 외부로 관찰되는 결과를 검증한다.
- `DELETE`를 실제 HTTP로 호출하는 방 퇴장 통합 테스트 하나를 주 경계로 한다. Testcontainers MySQL에서 성공·비인증·비멤버·이미 퇴장한 멤버 결과와 트랜잭션 내 데이터 변경을 확인한다.
- 통합 테스트는 설문 응답 제거와 5-1 조건 재확인, 투표하지 않은 자격자의 분모 감소·즉시 판정·0명 만료, 이미 투표한 멤버의 표와 분모 보존을 검증한다.
- 통합 테스트는 장소 반응 제거와 확정 후보 보존, 멤버 `leftAt`, `MEMBER_LEFT` 방 활동 내역, 커밋 후 `member.left` 이벤트를 확인한다.
- 테스트 선례는 실제 HTTP와 Testcontainers MySQL을 사용하는 방 합류·읽기 API 통합 테스트 및 안건 투표 통합 테스트다.

## Out of Scope

- 프론트엔드 확인 창과 퇴장 화면 전환
- 방 삭제 또는 마지막 활동 멤버 퇴장 시 자동 상태 변경
- 확정된 안건의 투표, 코멘트, 등록 장소, 일정 블록 삭제
- 별도 `agenda.resolved` 또는 `room.status_changed` SSE 이벤트
- 방 멤버 재합류 허용, 방장 이전, 멤버 수 제한 변경
- DB 스키마 및 Flyway 마이그레이션

## Further Notes

- 이미 투표한 멤버의 `Vote`는 기록으로 보존하며, 그 표를 유효한 투표로 세는 `total_voter`도 줄이지 않는다. 투표 전 퇴장한 자격자만 분모에서 빠진다.
- 5-1은 사용자 제공 R-06 명세가 참조하는 설문 마감 조건이다. 이 저장소에서 해당 조건의 별도 구현은 확인되지 않았으므로, 구현 시 원본 5-1 규칙을 기준으로 검증해야 한다.
