## Problem Statement

여행방 멤버는 자신이 해당 방에 제출한 설문 응답을 다시 확인할 API가 필요하다. 응답에는 예산, 숙박 유형, 여행 페이스, 선호 활동, 기피 메모, 제출 시각이 포함되며, 방 멤버십과 로그인 상태에 따라 조회할 수 있어야 한다.

## Solution

로그인한 활동 멤버가 `GET /api/rooms/{roomId}/survey/me`로 자신의 설문 응답을 조회한다. 제출한 응답이 있으면 기존 설문 선택지의 값과 라벨을 포함해 반환하고, 제출하지 않았다면 `SURVEY_NOT_FOUND`를 반환한다. 방이 없으면 `ROOM_NOT_FOUND`, 방의 멤버가 아니거나 나간 멤버라면 `FORBIDDEN`을 반환한다.

## User Stories

1. 로그인한 여행방 멤버로서, 내가 이 방에 제출한 설문을 조회하고 싶다. 그래야 제출한 응답을 다시 확인할 수 있다.
2. 설문 응답자로서, 응답의 설문 ID와 제출 시각을 받고 싶다. 그래야 어떤 제출 기록인지 확인할 수 있다.
3. 설문 응답자로서, 예산을 조회하고 싶다. 그래야 제출했던 여행 예산을 확인할 수 있다.
4. 설문 응답자로서, 숙박 유형과 여행 페이스의 코드 및 표시 라벨을 받고 싶다. 그래야 저장값과 화면에 표시할 문구를 함께 사용할 수 있다.
5. 설문 응답자로서, 선호 활동 목록의 코드 및 표시 라벨을 받고 싶다. 그래야 제출했던 선호를 다시 표시할 수 있다.
6. 설문 응답자로서, 기피 메모를 조회하고 싶다. 그래야 알레르기나 피하고 싶은 활동에 관한 내용을 확인할 수 있다.
7. 설문 중이 아닌 단계에서 응답한 멤버로서, 값이 없었던 예산·숙박 유형·여행 페이스를 `null`로 받아들이고 싶다. 그래야 방 단계에 따라 선택적으로 저장된 응답을 표현할 수 있다.
8. 응답을 제출하지 않은 활동 멤버로서, `404 SURVEY_NOT_FOUND`를 받고 싶다. 그래야 아직 내 설문이 없음을 알 수 있다.
9. 방에 속하지 않은 사용자로서, 조회가 `403 FORBIDDEN`으로 거부되길 원한다. 그래야 방 응답을 권한 없는 사용자가 볼 수 없다.
10. 방을 나간 사용자로서, 조회가 `403 FORBIDDEN`으로 거부되길 원한다. 그래야 이전 멤버십이 현재 접근 권한을 주지 않는다.
11. 존재하지 않는 방을 조회한 사용자로서, `404 ROOM_NOT_FOUND`를 받고 싶다. 그래야 잘못된 방 ID와 설문 부재를 구분할 수 있다.
12. 로그인하지 않았거나 세션이 만료된 사용자로서, `401 UNAUTHORIZED`를 받고 싶다. 그래야 인증이 필요한 API임을 알 수 있다.
13. 숫자가 아닌 방 ID로 요청한 사용자로서, `400 INVALID_INPUT`을 받고 싶다. 그래야 잘못된 경로 입력을 식별할 수 있다.
14. 여행방 멤버로서, 방 진행 단계나 여행 날짜와 관계없이 활동 멤버인 동안 설문을 조회하고 싶다. 그래야 제출 이후 방이 진행되어도 내 응답을 다시 볼 수 있다.
15. API 사용자로서, 성공 응답을 공통 `ApiResponse` 구조와 `SURVEY_FETCHED` 코드로 받고 싶다. 그래야 다른 API와 같은 방식으로 응답을 처리할 수 있다.

## Implementation Decisions

- 설문 도메인에 `GET /api/rooms/{roomId}/survey/me` 조회 API를 추가한다. 인증 사용자 ID는 controller에서 service로 전달한다.
- 응답 데이터는 `surveyId`, `budget`, `stayType`, `pace`, `actPrefs`, `avoidNote`, `submittedAt`을 포함한다. `budget`, `stayType`, `pace`는 설문 제출 당시 값이 없을 수 있으므로 nullable이다.
- `stayType`, `pace`, `actPrefs`의 항목은 `value`와 `label`을 제공한다. `value`는 enum 상수명, `label`은 기존 `StayType`, `Pace`, `ActivityCode` enum의 표시 라벨을 사용한다.
- `submittedAt`은 기존 규칙대로 오프셋 없는 `LocalDateTime`이며 한국 시간 기준이다.
- 성공은 HTTP 200이며 `ApiResponse` envelope와 `SURVEY_FETCHED` 코드를 사용한다.
- 인증 실패 또는 세션 만료는 401 `UNAUTHORIZED`다. 숫자가 아닌 `roomId`는 400 `INVALID_INPUT`이다.
- 존재하지 않는 방은 404 `ROOM_NOT_FOUND`다. 방 멤버 기록이 없거나 해당 멤버가 나간 상태이면 모두 403 `FORBIDDEN`이다.
- 활동 멤버가 해당 방에 설문을 제출하지 않은 경우 404 `SURVEY_NOT_FOUND`다.
- 방 진행 상태 및 여행 날짜는 조회 허용 여부에 영향을 주지 않는다. 활동 멤버 여부만 접근 권한으로 확인한다.
- 조회는 기존 멤버·설문 데이터를 사용하며 스키마 변경이나 마이그레이션은 추가하지 않는다.
- 조회는 되돌리기 쉬운 API 계약이며 대안 간 장기적 트레이드오프가 없어 ADR은 추가하지 않는다.

## Testing Decisions

- 좋은 테스트는 내부 호출 구조가 아니라 실제 HTTP에서 관찰되는 인증, 상태 코드, 응답 코드와 응답 본문을 검증한다.
- 주 테스트 경계는 로그인 세션 및 Testcontainers MySQL을 사용하는 설문 조회 HTTP 통합 테스트다. 합의한 대로 이 단일 경계에서 정상 응답과 주요 오류 계약을 검증한다.
- 정상 응답에서는 모든 필드, enum 값과 라벨, nullable 값, 한국 시간 기준 제출 시각, HTTP 200 및 `SURVEY_FETCHED`를 확인한다.
- 오류 응답에서는 미인증, 잘못된 `roomId`, 방 없음, 비멤버, 나간 멤버, 미제출 응답 각각의 HTTP 상태와 error code를 확인한다.
- 다른 멤버의 설문이 반환되지 않고 현재 로그인 사용자의 제출 응답만 조회되는지 확인한다.
- 기존 선례는 실제 서버와 세션 인증을 사용하는 API 통합 테스트, Testcontainers MySQL, 설문 제출 및 설문 옵션 API 테스트다.

## Out of Scope

- 다른 멤버들의 설문을 조회하는 API
- 설문 응답 수정 및 삭제
- 설문 응답 제출 단계의 검증 정책 변경
- 프론트엔드 설문 화면 또는 설문 수정 UI
- 방 활동 내역이나 SSE 이벤트 추가
- DB 스키마 변경 및 마이그레이션

## Further Notes

- 현재 설문 제출은 멤버당 한 번만 허용하므로 이 API의 대상은 해당 멤버의 단일 설문 응답이다.
