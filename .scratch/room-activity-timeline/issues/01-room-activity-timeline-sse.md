# 01: 방 활동 타임라인과 SSE 공통 전달 구현

**What to build:** 도메인들이 공통 방 활동 내역을 발행하고, 활동 멤버가 방별 SSE 연결로 타임라인을 실시간 조회·복구할 수 있습니다.

**Blocked by:** None (기존 방 활동 내역 저장 구조 사용)

**Status:** ready-for-agent

- [ ] 공통 발행·구독 경계에서 방 활동 기록을 커밋 후 방 구독자에게 전달한다.
- [ ] 활동 멤버 인증과 권한 검사를 거쳐 방별 SSE 연결을 연다. 비활성 멤버가 나가면 연결을 종료하고 재접속을 거부한다.
- [ ] 연결 등록 후 기준 활동 ID를 준비 이벤트로 보내 초기 타임라인 조회와 SSE 실시간 수신 사이의 누락을 막는다.
- [ ] 타임라인 페이지 API는 최신순 ID 커서 페이지를 제공한다. 초기 조회와 SSE 수신은 활동 ID로 중복을 제거해 합친다.
- [ ] SSE 재연결은 Last-Event-ID 이후 기록을 오름차순으로 재생하며, 누락이 200건을 넘으면 `resync.required`를 반환한다.
- [ ] ID가 없는 일시 이벤트는 저장하거나 재연결 시 재생하지 않는다.
- [ ] 화면에 실제 표시된 마지막 활동의 `createdAt`을 `LocalDateTime` `seenUntil`로 전달해 확인 시각을 갱신하며 기존 확인 시각보다 과거로 이동하지 않는다.
- [ ] 인증 포함 HTTP 통합 경계 하나에서 타임라인·SSE·재연결·재동기화·권한·읽음 처리를 Testcontainers MySQL로 검증한다.
- [ ] 새 도메인 활동과 같은 방의 동시 기록이 공통 계약을 통해 안전한 ID 순서로 전달되는지 검증한다.

## Comments

- 테스트 seam 합의: 인증 포함 HTTP 통합 테스트 하나를 사용하고 화면 상호작용은 명세 계약으로 둔다. 저장소에는 프론트엔드 코드와 UI 테스트 하네스가 없다.
