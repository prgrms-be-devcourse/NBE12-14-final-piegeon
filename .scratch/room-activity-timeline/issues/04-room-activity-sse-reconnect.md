# 04: SSE 재연결과 재동기화

**Parent:** 01: 방 활동 타임라인과 SSE 공통 전달 구현

**What to build:** 연결이 끊겼다가 복구되어도 활동 멤버가 놓친 영속 방 활동을 순서대로 다시 받을 수 있습니다.

**Blocked by:** 02: 방별 SSE 실시간 활동 전달

**Status:** ready-for-agent

- [ ] Last-Event-ID 이후 해당 방의 영속 활동을 오름차순으로 재생한다.
- [ ] 다른 방의 활동은 재생되지 않고, 활동 멤버가 아닌 사용자의 재연결은 거부된다.
- [ ] 누락 기록이 200건 이하이면 전체를 순서대로 재생한다.
- [ ] 누락 기록이 200건을 초과하면 일부를 재생하지 않고 `resync.required` 이벤트를 보낸다.
- [ ] `resync.required`는 영속 기록 ID가 없는 제어 이벤트다. 클라이언트는 기존 SSE 연결을 닫고 필요한 화면 데이터를 다시 조회한 뒤 새 연결을 연다.
- [ ] 재연결 재생은 영속 활동에만 적용하고 ID가 없는 일시 이벤트는 재전송하지 않는다.
- [ ] 통합 테스트에서 마지막 수신 ID 경계, 이벤트 순서, 방 격리, 정확히 200건 재생과 201건 초과 재동기화를 확인한다.
