# 방 활동 내역을 여러 도메인이 공유하는 영속 기록으로 관리

방 활동 내역은 방별로 관리하는 추가 전용 기록이며, 도메인 서비스가 상태 변경과 같은 트랜잭션에서 `ChangeLogService`를 통해 저장한다. 업무 행위 하나마다 의미상 이벤트 종류, 대상 종류와 ID, 행위 상태, 선택적 방 멤버 행위자, 당시 요약 문구를 한 건으로 남긴다. 대상이 삭제되어도 기록은 보존하고 방이 삭제되면 함께 삭제한다. 타임라인, 비접속 요약, SSE 재연결은 같은 기록을 사용하며, 로그 ID를 안전한 재연결 커서로 쓰기 위해 방별 기록 트랜잭션을 직렬화한다. ID가 없는 일시적 SSE 이벤트는 기록하지 않고, 실시간 전파는 트랜잭션 커밋 뒤에 수행한다.

방 활동 타임라인은 방별 SSE 연결에서 영속 활동을 받아 최신순으로 누적한다. 최초 연결은 구독을 등록한 뒤 현재 마지막 활동 ID를 기준점으로 준비 이벤트를 보낸다. 클라이언트는 기준 ID까지 활동을 조회하고, 조회가 끝날 때까지 수신한 이벤트를 버퍼링한 뒤 ID로 중복 제거해 합친다. 최신 항목을 보고 있을 때는 새 활동을 맨 위에 추가하고, 이전 항목을 읽는 동안에는 읽던 위치를 유지하며 새 활동 표시를 제공한다. 이전 페이지는 가장 오래된 항목보다 작은 ID로 조회한다. 사용자가 실제로 표시한 활동까지만 확인하며, 마지막으로 표시한 활동의 `createdAt`을 기존 확인 API의 `LocalDateTime` `seenUntil` 값으로 전달한다. 대상이 남아 있으면 해당 화면으로 이동하고, 삭제되었거나 이동할 수 없으면 기록을 그대로 표시한다.

각 도메인은 커밋된 기록을 공통 발행·구독 계약으로 전달하며, SSE 재생은 기존 방별 로그 ID와 200건 제한을 따른다. 전송 직전 서버 종료로 실시간 전달이 빠진 경우 재접속 재생으로 복구한다. 이번 설계는 단일 서버 연결 관리를 대상으로 하며 다중 서버 간 실시간 전파는 배포 요구가 생기면 별도 확장한다. 방 멤버가 나가면 해당 방의 활성 연결을 종료하고 이후 재접속을 거부한다. 개인 알림은 방 공통 활동과 별도 개념으로 둔다.
